# Как разобраться в проекте

## 1. Начни с запуска

Открой `Main.java`. Метод `main` создаёт три объекта:

- `Scanner` читает строки с клавиатуры.
- `Calculator` выполняет вычисления.
- `ConsoleCalculator` организует диалог и вызывает калькулятор.

`PrintStream` отвечает за вывод. Ввод и вывод используют UTF-8.
Конструкция `try (...)` автоматически закрывает `Scanner` при завершении.

## 2. Проследи один расчёт

Запусти приложение и введи три строки: `+`, `0,1`, `0.2`.

1. `ConsoleCalculator.run()` получает строку `+`.
2. `Operation.fromSymbol()` превращает её в значение `Operation.ADD`.
3. `readNumber()` получает каждый операнд. `DecimalNumbers.parse()`
   заменяет запятую точкой, проверяет формат и создаёт `BigDecimal`.
4. `Calculator.calculate()` выбирает сложение через `switch`.
5. `DecimalNumbers.format()` убирает лишние нули из результата.
6. `calculateAndPrint()` добавляет запись в `ArrayList` и печатает результат.
7. Цикл снова предлагает выбрать операцию.

Поставь breakpoint в `Calculator.calculate()` и запусти **Debug 'Main.main()'**:
так можно увидеть значения `left`, `operation` и `right` непосредственно во время расчёта.

## 3. Почему используется BigDecimal

`double` хранит числа в двоичном виде. Многие десятичные дроби в таком
представлении приближённые, поэтому при вычислениях могут появляться
неожиданные цифры в конце результата.

В этом проекте число создаётся непосредственно из текста:

```java
BigDecimal left = new BigDecimal("0.1");
BigDecimal right = new BigDecimal("0.2");
BigDecimal result = left.add(right); // 0.3
```

Конструктор `new BigDecimal(0.1)` сначала получает уже приближённый `double`,
поэтому здесь используется конструктор из строки.

`BigDecimal` неизменяемый: `left.add(right)` возвращает новый объект,
не меняя `left`. Для бесконечных дробей, например `1 / 3`, нужно задать
правило округления. В проекте выбрано 10 знаков после запятой и `HALF_UP`:
округление к ближайшему значению, а при точной середине — от нуля.

Для сравнения значений в тестах применяется `compareTo()`: числа `2.5`
и `2.50` численно равны. Метод `equals()` у `BigDecimal` также учитывает
масштаб, то есть число знаков после запятой.

## 4. Как приложение переживает ошибки

Ошибки пользователя обрабатываются рядом с вводом:

- Неизвестный символ операции → сообщение и возврат к выбору операции.
- Некорректное число → повторный запрос этого же числа.
- Нулевой делитель → сообщение и возврат в меню; запись не попадает в историю.
- `q` или конец ввода → нормальное завершение.

`Calculator` сообщает о делении на ноль через `ArithmeticException`,
а консольный класс перехватывает её и выводит понятный текст.
Так вычислительный код остаётся пригодным и для другого интерфейса.

В `readNumber()` значение `null` означает, что пользователь закончил ввод.
`run()` проверяет его до вызова калькулятора.

## 5. Как читать тесты

Начни с `CalculatorTest`. `@ParameterizedTest` запускает один сценарий
с несколькими наборами данных из `@CsvSource`.
`assertEquals()` проверяет результат, а `assertThrows()` — ожидаемую ошибку.

Затем открой `ConsoleCalculatorTest`: `runSession()` передаёт текст
в `Scanner` и собирает весь вывод в `ByteArrayOutputStream`.
Поэтому тестам не нужна настоящая клавиатура и они могут выполняться на GitHub.

При добавлении функции сначала сформулируй ожидаемое поведение и крайние случаи,
затем внеси изменение и запусти `mvn test`.

## Что уметь объяснить при показе проекта

| Вопрос | Где искать ответ |
| --- | --- |
| Почему несколько классов? | У каждого своя задача: ввод, расчёт, преобразование, запуск |
| Зачем enum? | Задаёт ограниченный набор допустимых операций |
| Почему BigDecimal? | Нужна предсказуемая десятичная арифметика |
| Что происходит при неверном вводе? | Повторный запрос или возврат в меню |
| Как хранится история? | `List<String>` на основе `ArrayList`, только в памяти |
| Что делает Maven? | Собирает проект, скачивает зависимости тестов и запускает тесты |
| Что делает CI? | Проверяет сборку и тесты после отправки изменений на GitHub |

## Упражнения для собственного развития проекта

1. Добавь `%`: новое значение в `Operation`, ветку в `Calculator`, описание
   в справке и тесты обычного случая, отрицательных чисел и нулевого делителя.
2. Добавь команду показа количества выполненных расчётов. Продумай, должен ли
   счётчик сбрасываться после очистки истории.
3. Сделай точность деления параметром калькулятора и проверь неверную точность.
4. Добавь запись истории в UTF-8-файл. Обработай ситуацию, когда файл нельзя записать.

Для портфолио полезно самостоятельно выполнить хотя бы одно улучшение,
добавить тесты и сохранить отдельный осмысленный коммит. Это даст конкретный
пример изменения, которое ты сможешь уверенно объяснить.
